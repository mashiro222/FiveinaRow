# 好友联机

## 同一 Wi-Fi 下直接玩

1. 两人安装 v1.2.2 或更新版本。第一人在「联机房间」点击「开启局域网服务」。
2. 把页面显示的 `ws://局域网地址:8787/room` 发给朋友；朋友填写到房间服务地址，点击连接。
3. 第一人创建房间，把四位房间号发给朋友。朋友输入房间号进入。
4. 点击黑棋或白棋席位，输入 1–16 字的名字。两席已满时，新来者可以旁观。
5. 房主设置禁手及每手 30 秒、60 秒或 2 分钟，双方点击准备后开局。

开启服务的电脑及游戏需持续运行。首次启动时系统可能询问是否允许局域网连接；应允许游戏访问。如果朋友连接不上，检查双方网络、防火墙及 Wi-Fi 是否开启了设备隔离。`127.0.0.1` 只能给本机使用，朋友需要填写实际局域网地址。

## 跨网络联机

跨家庭网络需要一个可公开访问的房间服务。此仓库提供完整服务端，但**没有内置已经上线的公共服务**。双方需填写同一个服务地址；只有房间号无法跨不同服务寻找房间。

服务采用单个 Node.js 进程，房间暂存在内存，不需要数据库或 Rapfi 模型。Rapfi 在每位玩家自己的桌面游戏内计算胜率。不要使用多实例随机负载均衡，否则同一房间可能落到不同进程。

### Render 免费部署

仓库根目录的 `render.yaml` 声明一个 **Free Web Service**，使用 `server/Dockerfile`，健康检查为 `/health`。不创建数据库、磁盘、付费实例或预览环境。默认部署在 Virginia，关闭自动部署，避免仅更新桌面界面时重启服务、打断棋局。

1. 登录 [Render](https://dashboard.render.com/)，连接有权读取本仓库的 GitHub 账号。
2. 选择 **New → Blueprint**，选中 `mashiro222/FiveinaRow` 的 `main` 分支，使用根目录 `render.yaml`。
3. 检查预览中只有 `five-in-a-row-rooms` 一个服务、实例为 **Free / $0**，再部署。不要选择付费计划或添加数据库。
4. 等待状态为 **Live**，访问分配地址的 `/health`，应返回 `ok: true`。
5. 游戏中填写 `wss://分配的地址.onrender.com/room`。此处地址必须以控制台实际分配的为准，不要猜测子域名。
6. 在本机运行 `node scripts/test-room-service.mjs wss://分配的地址.onrender.com/room`，验证公网两名棋手、一名观众、落子同步与重连。

免费服务约 15 分钟无入站流量后休眠，下次连接通常需要约一分钟唤醒。客户端为首次连接保留最多两分钟并自动重试，界面可以取消等待；正常游戏通信会保持服务活跃，不设置外部保活任务。每月 750 免费实例小时由工作区共享，另有流量和构建额度。未添加付款方式时，超额会暂停相应功能；添加付款方式后流量及构建超额可能产生费用。详见 [Render 免费规则](https://render.com/docs/free)。

平台休眠、重启和重新部署均会清空房间。更新服务时请等现有对局结束，再从 Render 手动部署最新提交。免费版适合朋友间试玩，无法保证随时在线或对局不中断。

### 自行运行服务

本机开发：

```sh
pnpm install --frozen-lockfile
pnpm server
# 默认监听 0.0.0.0:8787；可用 PORT 和 HOST 环境变量调整。
```

容器部署（从仓库根目录执行）：

```sh
docker build -f server/Dockerfile -t yijian-rooms .
docker run -d --restart unless-stopped --name yijian-rooms -p 127.0.0.1:8787:8787 yijian-rooms
```

在有域名的服务器上，使用 Caddy / Nginx 或平台提供的 TLS 反向代理，将 WebSocket `/room` 与 HTTP `/health` 转发到 `127.0.0.1:8787`。例如 Caddy：

```caddy
rooms.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

游戏内填写 `wss://你的域名/room`。平台部署需要：单实例、支持 WebSocket、端口取环境变量 `PORT`、健康检查 `/health`、持续运行。服务重启或平台休眠会清空房间，所有对局中止；生产使用不休眠实例。

确定正式服务地址后，可以设置 `src/online-client.js` 中的 `DEFAULT_ROOM_SERVER` 并重新打包，玩家首次进入即可使用该地址。

## 对局规则及生命周期

- 房间号范围 `0000`–`9999`。随机候选必须通过服务端查重；冲突会重新分配。默认最多 1,000 间房、每房 100 人；四位房号仅是加入入口，不是保密凭证。
- 创建/进入房间默认旁观。服务端原子处理入座请求，仅允许两名有名字的棋手。没有注册、聊天或账号资料。
- 房主可在开局前修改禁手和每手时限。修改后双方准备状态清除。双方入座、在线、准备后立即开局，黑棋先走。
- 使用标准 15 路棋盘，不使用交换开局。黑棋禁手按现有规则引擎校验；违法落点被拦截且时钟继续，超时判负。自由规则下五子或以上获胜。
- 时间以服务端为准，客户端时钟只负责显示。收到落子时再次检查截止时间。禁止旁观者落子、越权落子、覆盖棋子和旧棋局请求。
- 掉线后自动重连，30 秒内可恢复原席位、棋盘和计时，落子时钟不会暂停。超出 30 秒判负并释放席位。如果每手时限先到，则先判超时。主动离开进行中的对局等同认输。
- 房主退出后自动移交给剩余成员。双方可以准备再战，观众可在空位出现且棋局未进行时入座。
- 从最后一人断线/离开时开始，空房间保留 10 分钟后删除；删除后房间号可以复用。重启服务不会恢复房间。
- 联机对局不覆盖本机离线存档，也不混入与 AI 的胜率统计。

## Rapfi 胜率

对局中，每次落子后启动约 1.5 秒的 Rapfi 分析，显示其 `INFO WINRATE` 输出。引擎分数从「轮到落子的一方」统一换算成黑白两方的百分比。分析使用单独进程、2 个线程、128 MiB 置换表，不会替棋手落子或展示推荐落点。

这是本机引擎的局势估计，不是统计胜率或必胜证明；双方机器算力不同可能得到不同数值。引擎未返回有效评估时显示等待，不编造 50%。隐藏胜率或离开联机页面后暂停分析；返回会分析当前局面。对局计时仍继续。

## 验证

```sh
pnpm test           # 规则、房间状态机、真实 WebSocket 多客户端
pnpm test:native    # 原生 Rapfi、胜率方向、模型完整性
pnpm test:ui        # 原有离线页面回归
pnpm test:online    # 三个桌面客户端：两名棋手与一名观众
```

服务限制消息大小、发送频率、连接数、房间数和观众数，定期检测死连接。部署到公网时应在反向代理或平台配置连接/请求限制；代理前的同一 IP 连接上限默认为 40，按实际部署规模调整。会话令牌仅保存在玩家本机并经 WebSocket 传输，公网应使用 `wss://`。
